# Hem baseline and extension
Hem is an original small system for a neighbourhood garment-repair desk. Its display serif belongs to the workshop sign; monospaced labels identify jobs, units and due dates. Dark plum carries actions, dashed rules separate ticket labels from working content, and squared surfaces echo sewn-in garment labels. Status uses words plus contrasting surface/ink pairs. The visual language exists in the supplied source, not just this description.

The baseline runs directly over HTTP: index.html loads styles.css and app.mjs; styles imports source/tokens.css and source/primitives.css; the app imports source/contexts.mjs, whose views use source/primitives.mjs. It fetches two local JSON snapshots. No packages or build. Existing contexts: a three-job queue, a detail view and back navigation for every job, a material reference, and an interactive primitive specimen. The specimen's note/action is ephemeral and does not edit a job. Initial load shows the queue. Navigation focuses the main container. There is no estimate editor, customer approval, persistence, routing, search or job-status mutation. Do not claim those are implemented.

Extend this baseline with a useful estimate workflow on each job. Staff need to add, adjust and remove labour and material lines, see unit and extended costs and a total before tax, approve a local snapshot, and revise it. Labour is counted in 15-minute units; quantity 1–16 per line. Materials use quantities 1–10 per line. All identifiers and costs come from rates.json. Duplicate lines are permitted: do not invent consolidation or pruning rules. Empty estimates may be drafted, but cannot be approved. Approval is a local workshop action, not a message, signature, charge or change to the job's queued/in-progress/ready status.

Provide separate in-memory drafts for each job. Navigating away and back retains that job's work for the current page session. Approving captures the displayed line items and total. Editing or removing a line after approval visibly returns that estimate to draft; the old approval cannot silently cover a changed amount. Invalid quantities are explained without discarding other input. A full reload may reset the demo, and should say so. Keep the supplied queue, detail, materials and primitive contexts reachable and functional. Add new primitives or variants if the work needs them and expose them in the specimen context alongside existing ones. The missing estimate is real work, not a request to redesign finished screens.

Use the existing tokens and import the actual primitive module in the extension view at source/estimate-view.mjs; do not rebuild a disconnected imitation. You may edit all supplied source files and add tokens with a clear semantic purpose. Existing text, job facts, catalog facts and behavior must remain available. There is no requirement to remove or promote components to manufacture an architectural puzzle. Decide the estimate composition and transitions yourself. Document your additions and browser inspection honestly in CHANGES.md.

Implement logic.mjs export quote(lines, rates), and call it from source/estimate-view.mjs. Each input line is {kind:"labour"|"material", id, quantity}. Return {lines:[{kind,id,quantity,unitCents,totalCents}],totalCents}. Preserve order and duplicate lines. Match IDs against rates.labour or rates.materials; accept only integer quantities in the above limits; unknown kinds/IDs or invalid quantities throw RangeError. Empty input returns {lines:[],totalCents:0}. Do not mutate lines or rates. Approval/draft state is UI work, tested by human browser probes rather than inferred from quote arithmetic.

All required output paths: index.html, styles.css, app.mjs, logic.mjs, CHANGES.md, source/tokens.css, source/primitives.css, source/primitives.mjs, source/contexts.mjs, source/estimate-view.mjs, data/jobs.json, data/rates.json. Snapshotted data is immutable and already mounted. Supplied source is editable and mounted into the named output paths; logic.mjs, source/estimate-view.mjs and CHANGES.md are missing on purpose. app.mjs must import source/estimate-view.mjs as well as the existing contexts; the extension imports primitives.mjs and ../logic.mjs. Optional authored assets go in assets/. No dependencies, build tools, remote fonts or network services. Work at 360px and 1440px, with keyboard control and accessible feedback. Run node validation/validate-output.mjs.
